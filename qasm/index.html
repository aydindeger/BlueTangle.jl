OpenQASM import and export

from_qasm turns an OpenQASM 2 program into an ordinary vector of BlueTangle operations. You can inspect or edit that vector, apply it to a state, and choose a simulation backend. to_qasm writes the supported operations back to text or a file.

Import a string

using BlueTangle

source = """
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
h q[0];
cx q[0], q[1];
"""
ops = from_qasm(source; is_file=false)
state = apply(zero_state(get_N(ops)), ops)
@assert correlation(state, "X,X", [1, 2]) ≈ 1
@assert correlation(state, "Z,Z", [1, 2]) ≈ 1
(qubits=get_N(ops), gates=length(ops))
(qubits = 2, gates = 2)

OpenQASM indices start at 0, whereas BlueTangle indices start at 1. The importer translates them. BlueTangle's statevector basis still places physical qubit 1 in the most significant bit.

Read a file and round-trip a circuit

restored = mktempdir() do directory
    path = joinpath(directory, "bell.qasm")
    to_qasm(ops, path)
    from_qasm(path; is_file=true)
end
@assert apply(zero_state(get_N(restored)), restored) ≈ state
println(to_qasm(restored))
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg c[2];
h q[0];
cx q[0],q[1];

For an existing file, use from_qasm("circuits/bell.qasm"; is_file=true). Without is_file, an existing path is read as a file and recognizable program text is parsed directly. Explicit is_file=false is useful when a string should always be interpreted as source.

Registers and broadcasts

Multiple quantum registers are flattened in declaration order. A declared idle tail is preserved, so a four-qubit register remains four qubits even if only q[0] is acted on. A trailing identity may be added to carry that size in the operation-vector API.

Whole-register operations expand in register-index order. Equal-sized registers can be paired, and a scalar operand can be broadcast against a register:

using BlueTangle
ops = from_qasm("""
OPENQASM 2.0;
qreg data[2];
qreg anc[2];
h data;
cx data, anc;
""")
state = apply(zero_state(get_N(ops)), ops)
@assert get_N(ops) == 4
@assert correlation(state, "Z,Z", [1, 3]) ≈ 1
@assert correlation(state, "Z,Z", [2, 4]) ≈ 1
(data_register=[1,2], anc_register=[3,4])
(data_register = [1, 2], anc_register = [3, 4])

Here data[0:1] becomes BlueTangle qubits 1–2 and anc[0:1] becomes qubits 3–4. The notation in that sentence describes the register range; it is not a supported OpenQASM slice expression. Use a full register name or one indexed element in source. Register sizes and indexed bounds are checked.

Measurement records and reset

An imported measure becomes an explicit mid-circuit MZ. run returns those outcomes in operation order:

using BlueTangle
source = """
OPENQASM 2.0;
qreg q[2];
creg c[2];
x q[1];
measure q -> c;
reset q;
"""
records = run(source, 3)
@assert records == [[0,1],[0,1],[0,1]]
records
3-element Vector{Vector{Int64}}:
 [0, 1]
 [0, 1]
 [0, 1]

The destination classical bits are validated, but the returned object is an operation list, not a classical-register simulator. Records do not reconstruct arbitrary classical-register assignments. Classical if statements are rejected; express feed-forward directly with BlueTangle's conditional Op or ifOp when constructing a circuit in Julia.

For final sampling, call measure(from_qasm(source), shots; backend=:density_matrix) or choose :statevector or :tensor. In the example above the explicit reset leaves the final state in |00⟩, although the earlier record is [0,1].

Numeric parameters and diagnostics

Parameters accept finite real arithmetic, pi/π, implicit multiplication, and supported numeric functions such as sin, cos, sqrt, exp, and ln:

using BlueTangle
ops = from_qasm("qreg q[1]; ry(sin(pi/4) + 2^-2) q[0];")
@assert only(ops).mat ≈ _RY(sin(pi/4) + 0.25)

These expressions are parsed without executing Julia code. Assignments, macros, module access, indexing, and arbitrary function calls are not accepted.

Errors identify the source, line, and statement:

using BlueTangle
try
    from_qasm("OPENQASM 2.0;\nqreg q[2];\nx q[2];")
catch error
    println(sprint(showerror, error))
end
ArgumentError: <string>:3: ArgumentError: Qubit q[2] is outside its register.
  x q[2];

Supported subset

The importer supports OPENQASM 2.0, include "qelib1.inc", qreg/creg, barriers, reset, and measurement, with these gates:

FamilyNames
One qubitid, x, y, z, h, s, sdg, t, tdg, sx, sxdg
Parameterized one qubitrx, ry, rz, p, u1, u2, u3, U
Controlledcx/cnot, cy, cz, ch, crx, cry, crz, cp/cu1, cu2, cu3
Two qubitsswap, iswap, fswap, syc, ecr, rxx, ryy, rzz, rxy, givens, fsim, swapa
Three qubitsccx, ccy, ccz, cswap

Custom gate definitions, classical conditions, arbitrary include files, and OpenQASM 3 constructs require a separate conversion before import. Unsupported statements fail explicitly.

Export preserves the represented gate matrices within floating-point tolerance. For X/Y measurements, it writes the basis rotation, Z measurement, and inverse rotation, so subsequent quantum operations see the same post-measurement state. Some nonstandard gates are declared opaque; another tool must know their semantics to execute them. In particular, BlueTangle uses RXX(theta) = exp(-im*theta*X⊗X) and the analogous full-angle RYY convention; check angle conventions when exchanging those gates with another simulator.

BlueTangle.from_qasm — Function
from_qasm(qasm_or_path::AbstractString; is_file=nothing) -> Vector{QuantumOps}

Read the supported OpenQASM 2 gate subset from text or a file. Quantum registers are flattened in declaration order, preserving idle qubits. Numeric parameters use the same restricted arithmetic parser as gates. Indexed operands and whole-register broadcasts are supported. Set is_file=true or false to select file or string input explicitly. Parse errors identify the source and line. Custom gate definitions and classical if statements must be expanded before import. Measurement records follow operation order, not classical-register layout.
