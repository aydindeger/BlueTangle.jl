Calculate the correlation for a given set of operators applied to specific qubits in either a quantum state vector or a density matrix. This function has two primary forms:

  • correlation(state::AbstractVectorS, list_of_operators::String, qubits_applied::Vector): Computes the correlation for a quantum state vector (state) with a specified list of operators and qubits.

  • correlation(rho::AbstractMatrixS, list_of_operators::String, qubits_applied::Vector): Computes the correlation for a density matrix (rho) with a specified list of operators and qubits.

The corr_from_rho function is an alias to get_corr for density matrices.

  • state::AbstractVectorS: The quantum state vector.
  • rho::AbstractMatrixS: The density matrix.
  • list_of_operators::String: A string representing a list of operators, e.g., "Z,Z".
  • qubits_applied::Vector: A vector of qubit indices on which the operators are applied.

Returns

  • Float64: The computed correlation value.

Examples

# For a state vector
state = sa.SparseVector([...]) # define your state vector
correlation = correlation(state, "Z,Z", [2, 4])

# For a density matrix
rho = sa.SparseMatrixCSC([...]) # define your density matrix
correlation = correlation(rho, "Z,Z", [2, 4])

Base.run — Method
run(ops, shots=1; options=Options(), N=get_N(ops), layout=nothing,
    backend=:statevector, kwargs...)
run(qasm_or_path::AbstractString, shots::Int=1; backend=:statevector, kwargs...)

Return one vector of explicit mid-circuit measurement bits per shot, starting each shot in |0…0⟩. Outcomes 0 and 1 denote the +1 and −1 eigenvalues of the measured Pauli. Records follow operation-list order and include measurements inside the chosen conditional branch. Reset adds no bit, and no final measurement is appended; use measure for final-outcome sampling.

Choose :statevector, :density_matrix, or :tensor (:mps). MPS accepts cutoff and maxdim, including for conditional branch operations. Density-matrix execution conditions on the recorded measurements but still sums noise and reset Kraus branches. For a custom initial state and literal operation-list order, use apply(initial, ops; track_measurements=true). N can include idle qubits. Routing is performed only when layout is supplied.

BlueTangle.shadow — Function
shadow(ops, number_of_experiment::Int; options=Options(), N=get_N(ops),
       layout=nothing, qubits=nothing, backend=:statevector, kwargs...)

Estimate a reduced density matrix using uniformly random local X, Y, Z measurements. qubits selects the retained qubits (an integer or a collection of distinct indices). The returned sparse matrix has size 2^k × 2^k for k selected qubits, in ascending qubit order, as in partial_trace. Omitting qubits preserves the full-system estimate.

Each shot contributes the tensor product, over the selected qubits only, of (I + 3*(-1)^b*P)/2, where P is the measured Pauli and b is its outcome. Tracing out other qubits simply removes their trace-one factors; no full density matrix is constructed when requesting a subsystem.

The default backend=:statevector uses a 2^N statevector. Use backend=:tensor (or :mps) to evolve and sample an MPS directly, without constructing a full statevector. The MPS backend accepts cutoff and maxdim; truncation introduces simulation error in addition to sampling error, and cost depends on the bond dimensions. Both backends repeat preparation for every shot, including any circuit noise or mid-circuit measurements.

With ideal readout, the estimator is unbiased for the simulated state, Hermitian and trace one, but need not be positive at finite shot counts. Its eigenvalues are not probabilities and cannot be used directly to estimate entropy. Readout noise and readout mitigation are unsupported and raise an ArgumentError. The final measurement_basis is replaced by independent random Pauli bases. Operations run in their listed order; routing is performed only when layout is supplied. N can include idle qubits, and omitted qubits selects all qubits.

rho_13 = shadow(ops, 10_000; qubits=[1, 3]) # only a 4 × 4 estimate
rho_2 = shadow(ops, 10_000; qubits=2)       # only a 2 × 2 estimate
rho_13_mps = shadow(ops, 10_000; qubits=[1, 3], backend=:mps, cutoff=1e-12)

linear_fit(xdata::Vector, ydata::Vector)

Description

This function fits a simple linear model (y = a + b*x) to the provided data points. It checks if the lengths of xdata and ydata are the same and then calculates the coefficients for the linear fit. Additionally, it computes the standard errors for both the slope and the intercept.

BlueTangle.Op — Type
Op(name, qubit[, target_qubit]; noisy=true, control=-2)
Op(name, matrix_or_function, qubit[, target_qubit]; noisy=true, control=-2)

Construct a built-in gate, custom matrix gate, or parameterized gate function. Qubits are numbered from 1; qubit 1 is the most significant bit. noisy controls whether the circuit's noise model is applied after this gate, and control optionally adds a control qubit.

The common Op entry point also accepts a channel (Op(channel, qubit)), a measurement with conditional branches (Op("MZ", qubit; if0="I", if1="X")), or a named whole-register block (Op(name, operations_or_matrix_or_callback)). These constructors return OpQC, ifOp, or OpF as appropriate.

Op("RESET", qubit) and Op("RES", qubit) return the ideal reset channel to |0⟩. Reset adds no measurement bit, even with track_measurements=true. Use ifOp("MZ", qubit, "I", "X") with tracking to retain the pre-reset outcome. Those explicit feedback gates receive gate noise by default; use Op("I", qubit; noisy=false) and Op("X", qubit; noisy=false) as the branches when the correction should be ideal under a gate-noise model.

source
BlueTangle.ifOp — Type
ifOp(name, qubit, if0, if1)

Measure a qubit in the X, Y, Z, or uniformly random Pauli basis ("MX", "MY", "MZ", or "MR"), then apply the branch for outcome 0 or 1. Each branch is an Op or a vector of Ops. Two gate-name strings instead act on the measured qubit.

For example, ifOp("MZ", 1, Op("I", 1), Op("X", 2)) flips qubit 2 only when qubit 1 is measured as 1. Equivalently, use the common constructor Op("MZ", 1; if0=Op("I", 1), if1=Op("X", 2)).

Vector and MPS evolution sample the measurement. Density-matrix evolution sums both branches unless track_measurements=true requests a conditional state. Tracked records include the outer outcome followed by measurements in the chosen branch. MPS cutoff and maxdim settings also apply to branch operations.

BlueTangle.Options — Type
Options(; circuit_name="circuit", measurement_basis="Z", noise=false,
          twirl=false, readout_noise=false, measurement_mitigate=false,
          density_matrix=false)

Configure circuit execution and final measurement. noise accepts a NoiseModel; readout_noise accepts a single-qubit channel applied before final readout. measurement_mitigate inverts that channel's classical readout response, retaining signed estimates at finite shot counts. It requires an invertible response whose output populations do not depend on input coherences; other channels are rejected. These weights sum to one but need not be probabilities; observable estimates can exceed their physical range due to sampling error. density_matrix requests storage of the final density matrix in measurement results; select the simulation backend separately with measure(ops, shots; options, backend=:density_matrix).

twirl=true enables Pauli twirling of supported two-qubit gates. Routing swap noise is configured separately through Layout(...; noisy_swap=true).

BlueTangle.gate — Constant

gate

A constant that holds common quantum gates and projectors.

This includes:

  • Identity (I)
  • Pauli gates (X, Y, Z)
  • Hadamard (H)
  • Phase gates (S, T)
  • Special gates like sqrt(X) (equal to RX(pi/2)exp(1impi/4))
  • Projectors (P0 for |0><0|, P1 for |1><1|)
  • Controlled gates such as CX (CNOT), CNOT (an alias for CX), and CZ
  • The SWAP, ISWAP, FSWAP gate
  • The ECR, SYC gate

Each single-qubit gate is represented as a 2x2 matrix, while multi-qubit gates like CNOT, ECR, SYC, CZ, and SWAP, ISWAP, FSWAP are represented as 4x4 matrices.

BlueTangle.random_ops — Function
random_ops(N, depth; measure_prob=0.0, measure_basis=["MX", "MY", "MZ"])

Generate depth layers of random single-qubit and nearest-neighbor two-qubit gates on an open chain. Each unitary layer covers the qubits with disjoint gates. After each layer, independently measure each qubit with probability measure_prob, choosing its basis uniformly from measure_basis.

The returned vector contains both gates and measurements; depth counts unitary layers, not individual operations. This uses the package's discrete gate family and random rotation parameters, rather than Haar-random two-qubit unitaries.

Example

ops = random_ops(5, 10; measure_prob=0.2, measure_basis=["MX","MZ"])

This creates ten unitary layers on five qubits, each followed by independently chosen X- or Z-basis measurements with probability 0.2 per qubit.

BlueTangle.random_clifford — Function

random_clifford(N::Int, len::Int; measure_prob::Float64=0.0, measure_basis::Vector{String}=["MX","MY","MZ"]) -> Vector{QuantumOps}

Generate a random sequence of Clifford gates, with optional mid-circuit measurements.

Arguments

  • N::Int: The number of qubits in the system.
  • len::Int: The length of the sequence of operations to generate.

Keyword Arguments

  • measure_prob::Float64: The probability of adding a measurement operation after each gate.
  • measure_basis::Vector{String}: The basis in which measurements are performed.

Returns

  • Vector{QuantumOps}: A vector of randomly chosen quantum operations (QuantumOps), each representing a Clifford gate or a measurement operation.

Description

This function creates a vector of quantum operations, where each operation is either a randomly chosen Clifford gate from the set {"X", "Y", "Z", "H", "S", "CNOT", "SWAP", "CZ"} or a measurement operation, based on measure_prob. For two-qubit gates ("CNOT", "SWAP", "CZ"), adjacent qubits (qubit r and qubit r+1) are selected. For single-qubit gates and measurements, a random qubit r is chosen.

Example

ops = random_clifford(5, 10; measure_prob=0.2, measure_basis=["MX","MZ"])

This example generates a sequence of 10 random Clifford gates and measurements (with a 20% chance of a measurement after each gate) for a 5-qubit system.

Amplify the presence of CNOT (or CX) operations in a vector of quantum operations.

This function adds extra pair of CNOT operation in the ops vector a specific number of times in place. This is useful for amplifying the effect of noise via CNOT operations in a sequence of quantum operations.

Arguments

  • ops::Vector{<:QuantumOps}: A vector of quantum operations, where T is a subtype of QuantumOps.
  • CNOT_pair::Int (optional): The number of additional pairs of CNOT operations to insert for each original CNOT operation in ops. The default value is 0, which means no additional operations are inserted.

BlueTangle.hamiltonian — Function

hamiltonian(N::Int, string_of_ops::Vector, boundary::String="open")

Constructs a Hamiltonian matrix for a quantum system with N qubits. The Hamiltonian is built based on the operators and their corresponding couplings specified in string_of_ops.

The string_of_ops should be an alternating array of coupling constants and operator strings. For example, [.1, "Z,Z", .5, "X"] implies a system with alternating couplings .1 and .5, and operators "Z,Z" and "X".

The boundary parameter specifies the boundary conditions of the system. It can be either "open" or "periodic". In the case of "open" boundary conditions, interactions are only included for sites within the system size. For "periodic" boundary conditions, the system is treated as if it were wrapped around itself, allowing interactions that cross the end and start of the chain.

Arguments

  • N::Int: The number of qubits in the system.
  • string_of_ops::Vector: An alternating vector of coupling constants and operator strings.
  • boundary::String: The boundary condition of the system, either "open" or "periodic" (default is "open").

Returns

  • SparseMatrix: The Hamiltonian matrix representing the specified quantum system.

Example

N = 6
string_of_ops = [-J, "Z,Z", -h, "X"]
H = hamiltonian(N, string_of_ops, "open")

This function iterates over the operator strings, applies each operator to the appropriate qubits based on the boundary conditions, and scales them by their corresponding coupling constants to construct the Hamiltonian.

BlueTangle.hamiltonian_exp — Function
hamiltonian_exp(N, total_time, terms; dt=0.01, full=true)
hamiltonian_exp((rows, cols), total_time, terms; dt=0.01, full=true, enumeration_style=:rowwise)

Construct a first-order Trotter approximation to exp(-im*total_time*H) for H = hamiltonian(N, terms) with open boundaries. terms alternates real couplings and comma-separated Pauli strings, for example [0.7, "X,Z", 0.2, "Y"]. Identity factors preserve the separation between the active sites. In 2D, strings run along both lattice directions; single-site terms are counted once.

The last step is shortened to reach the requested time exactly. full=false returns just one step of duration dt (with the sign of total_time).
