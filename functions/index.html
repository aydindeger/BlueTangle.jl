Measurement functions

BlueTangle.sample — Function
sample(ops, shots; options=Options(), N=get_N(ops), layout=nothing,
       backend=:statevector, kwargs...)
sample(qasm_or_path::AbstractString, shots::Int=1; options=Options(),
       layout=nothing, backend=:statevector, is_file=nothing, kwargs...)

Return raw final outcomes as integers, starting each shot in |0…0⟩. ops may be a vector of QuantumOps, tuple shorthands such as [("H", 1), ("CX", 1, 2)], or a mix of both. Qubit 1 is the most significant bit. Noisy statevector, MPS, and CAMPS circuits use independent trajectories; density-matrix evolution sums unobserved noise branches. Per-shot explicit mid-circuit measurement records are available via measure(ops, shots).mid_measurements, or for a single evolved state via apply(state, ops; track_measurements=true).

The backend, routing, measurement basis, readout noise, and twirling options match measure. Use measure for summary statistics or readout mitigation: raw outcomes cannot include mitigated signed weights.

source
sample(state, shots) -> Vector

Return raw computational-basis outcomes sampled from a statevector, density matrix, or MPS. Outcomes are integers starting at 0; qubit 1 is the most significant bit. The state is not collapsed. Use measure(state, shots) for summary statistics or measure(state) for exact probabilities.

BlueTangle.measure — Function
measure(state; label="state to measurement")
measure(state, shots; label="state to measurement")

Return device-like measurement statistics for a statevector, density matrix, MPS, or CAMPSState. Omitting shots uses exact probabilities; a positive count uses sampled frequencies. Exact MPS and CAMPS enumeration is limited to 16 qubits, so pass a shot count for larger states. Use sample(state, shots) for raw outcomes.

source
measure(ops, shots; options=Options(), N=get_N(ops), layout=nothing,
        backend=:statevector, kwargs...)
measure(qasm_or_path::AbstractString, shots::Int=1; options=Options(),
        layout=nothing, backend=:statevector, is_file=nothing, kwargs...)

Return device-like final-outcome statistics (and per-shot mid_measurements records when the circuit contains explicit MX/MY/MZ/MR/ifOp operations) from fresh circuit shots starting in |0…0⟩. ops may be a vector of QuantumOps, tuple shorthands such as [("H", 1), ("CX", 1, 2)], or a mix of both. sample(ops, shots) returns the corresponding raw integer outcomes.

Choose statevector (:statevector), density-matrix (:density_matrix), MPS (:tensor / :mps), Clifford-augmented MPS (:camps), or optional PhasePoly (:phasepoly, requires import PhasePoly) evolution. MPS accepts cutoff and maxdim; :camps also accepts disentangle and nsweeps; :phasepoly accepts max_h, max_cccz, max_ccs, and max_nonzeros. N can include idle qubits. Operations run in their listed order, with routing only when layout is supplied. Readout noise, readout mitigation, basis selection, and twirling are configured through Options.

expect(state, op::QuantumOps)

Calculate expectations for a statevector or density matrix. An Op specifies the qubits on which the observable acts; a matrix acts on the full register. A single-qubit operator string returns one expectation per qubit. For one selected qubit, use expect(state, Op("Z", q)). Results are real-valued.

state = apply(zero_state(2), Op("X", 2))

@assert expect(state, gate.Z ⊗ gate.Z) ≈ -1
measurement = measure(state)
@assert expect(measurement, 2) ≈ measurement.expect[2] ≈ -1

BlueTangle.correlation — Function
correlation(m::Measurement, qubits::Vector)

Return the expectation of the product of measured eigenvalues on qubits. Each recorded bit contributes (-1)^bit; for Z-basis data, [1, 3] therefore gives ⟨Z₁Z₃⟩. The calculation uses the probabilities or signed weights in m.

source

Return the expectation of a product of single-qubit observables in a statevector or density matrix. Pair each comma-separated operator with the corresponding entry of qubits_applied; for example, "X,Z" on [1, 3] gives ⟨X₁Z₃⟩. The result is real-valued.

BlueTangle.apply — Function
apply(state, ops; noise=false, track_measurements=false, kwargs...)
apply(ops; N=get_N(ops), backend=:statevector, noise=false,
      track_measurements=false, layout=nothing, kwargs...)

Apply operations in their listed order to an existing state (:statevector, :density_matrix, :tensor/:mps, or CAMPSState), or starting from |0…0⟩ in the requested backend (:statevector, :density_matrix, :tensor, :camps, or :phasepoly). ops may be a single QuantumOps or tuple shorthand (e.g. ("H", 1)), or a vector of QuantumOps, tuple shorthands (e.g. [("H", 1), ("CX", 1, 2)]), or a mix of both.

By default, density matrices sum measurement and noise branches, while statevectors, MPS, and CAMPS follow one sampled trajectory. Pass track_measurements=true to return (final_state, bits), conditioning density matrices on the sampled measurement outcomes and recording each explicit mid-circuit measurement bit (MX, MY, MZ, MR, ifOp) in operation order. No routing or scheduling is performed unless layout is supplied.

BlueTangle.shadow — Function
shadow(ops, number_of_experiment::Int; options=Options(), N=get_N(ops),
       layout=nothing, qubits=nothing, backend=:statevector, kwargs...)

Estimate a reduced density matrix using uniformly random local X, Y, Z measurements. ops may be a vector of QuantumOps, tuple shorthands such as [("H", 1), ("CX", 1, 2)], or a mix of both. qubits selects the retained qubits (an integer or a collection of distinct indices). The returned sparse matrix has size 2^k × 2^k for k selected qubits, in ascending qubit order, as in partial_trace. Omitting qubits preserves the full-system estimate.

Each shot contributes the tensor product, over the selected qubits only, of (I + 3*(-1)^b*P)/2, where P is the measured Pauli and b is its outcome. Tracing out other qubits removes their trace-one factors. A subsystem estimate therefore requires only the factors associated with the retained qubits.

The default backend=:statevector uses a 2^N statevector. Use backend=:tensor (or :mps) to evolve and sample an MPS directly, backend=:camps for a Clifford-augmented MPS (CAMPSState), or backend=:phasepoly (after loading the optional PhasePoly package) for supported noiseless circuits. The MPS backend accepts cutoff and maxdim; :camps also accepts disentangle and nsweeps; :phasepoly accepts max_h, max_cccz, max_ccs, and max_nonzeros. Truncation introduces simulation error in addition to sampling error, and cost depends on the bond dimensions. All trajectory backends repeat preparation for every shot, including any circuit noise or mid-circuit measurements.

With ideal readout, the estimator is unbiased for the simulated state, Hermitian and trace one, but need not be positive at finite shot counts. Its eigenvalues are not probabilities and cannot be used directly to estimate entropy. Readout noise and readout mitigation are unsupported and raise an ArgumentError. The final measurement_basis is replaced by independent random Pauli bases. Operations run in their listed order; routing is performed only when layout is supplied. N can include idle qubits, and omitted qubits selects all qubits.

ops = [Op("H", 1), Op("CX", 1, 2), Op("CX", 2, 3)]
rho_13 = shadow(ops, 10_000; qubits=[1, 3]) # only a 4 × 4 estimate
rho_2 = shadow(ops, 10_000; qubits=2)       # only a 2 × 2 estimate
rho_13_mps = shadow(ops, 10_000; qubits=[1, 3], backend=:mps, cutoff=1e-12)

BlueTangle.Op — Type
Op(name, qubit[, target_qubit]; noisy=true, control=-2)
Op(name, matrix_or_function, qubit[, target_qubit]; noisy=true, control=-2)

Construct a built-in gate, custom matrix gate, or parameterized gate function. Qubits are numbered from 1; qubit 1 is the most significant bit. noisy controls whether the circuit's noise model is applied after this gate, and control optionally adds a control qubit.

The common Op entry point also accepts a channel (Op(channel, qubit)), a measurement with conditional branches (Op("MZ", qubit; if0="I", if1="X")), or a named whole-register block (Op(name, operations_or_matrix_or_callback)). These constructors return OpQC, ifOp, or OpF as appropriate.

Op("RESET", qubit) and Op("RES", qubit) return the ideal reset channel to |0⟩. Reset adds no measurement bit when tracking mid-circuit measurements. Use apply(state, ifOp("MZ", qubit, "I", "X"); track_measurements=true) (or measure(...).mid_measurements) to retain the pre-reset outcome. Those explicit feedback gates receive gate noise by default; use Op("I", qubit; noisy=false) and Op("X", qubit; noisy=false) as the branches when the correction should be ideal under a gate-noise model.

source
BlueTangle.ifOp — Type
ifOp(name, qubit, if0, if1)

Measure a qubit in the X, Y, Z, or uniformly random Pauli basis ("MX", "MY", "MZ", or "MR"), then apply the branch for outcome 0 or 1. Each branch is an Op or a vector of Ops. Two gate-name strings instead act on the measured qubit.

For example, ifOp("MZ", 1, Op("I", 1), Op("X", 2)) flips qubit 2 only when qubit 1 is measured as 1. Equivalently, use the common constructor Op("MZ", 1; if0=Op("I", 1), if1=Op("X", 2)).

Vector, MPS, and CAMPS evolution sample the measurement. apply(rho, op) sums both branches; apply(rho, op; track_measurements=true) returns a conditional density matrix and its measurement record. Records include the outer outcome followed by measurements in the chosen branch. MPS and CAMPS truncation settings also apply to branch operations.

BlueTangle.Measurement — Type
Measurement

Device-like measurement outcomes returned by measure or constructed from existing integer draws with Measurement(draws, N).

  • bitstr: Integer labels of computational-basis outcomes.
  • sample: Probabilities, sampled frequencies, or signed weights after readout mitigation.
  • expect: One eigenvalue expectation per qubit.
  • mag_moments: Moments of the total measured magnetization, for orders 1 through 12.
  • measurement_basis: Readout basis; "0" denotes direct state or sample summaries.

  • circuit_name: Label supplied by the caller.
  • number_of_qubits: Register size.
  • mid_measurements: Per-shot vectors of explicit mid-circuit measurement bits (MX, MY, MZ, MR, ifOp) recorded in operation order; empty when the circuit contains no explicit mid-circuit measurements or when summarizing a state/draw vector directly.

BlueTangle.QuantumChannel — Type
QuantumChannel(q::Int, model::String, p::Float64)

BlueTangle.Options — Type
Options(; circuit_name="circuit", measurement_basis="Z", noise=false,

Configure circuit execution and final measurement. noise accepts a NoiseModel; readout_noise accepts a single-qubit channel applied before final readout. measurement_mitigate inverts that channel's classical readout response, retaining signed estimates at finite shot counts. BlueTangle.gate — Constant
gate

Named tuple of common gate and projector matrices, accessed as gate.H, gate.CX, and so on. One-qubit matrices are 2×2 and two-qubit matrices are 4×4.

Entries include the identity and Pauli matrices, H, S, T and their adjoints, square roots of X, projectors P0 = |0⟩⟨0| and P1 = |1⟩⟨1|, controlled gates, SWAP/ISWAP/FSWAP, ECR, and SYC. CNOT aliases CX, and SX = exp(im*pi/4)*RX(pi/2).

BlueTangle.random_ops — Function
random_ops(N, depth; measure_prob=0.0, measure_basis=["MX", "MY", "MZ"])

Generate depth layers of random single-qubit and nearest-neighbor two-qubit gates on an open chain. Each unitary layer covers the qubits with disjoint gates. After each layer, independently measure each qubit with probability measure_prob, choosing its basis uniformly from measure_basis.

The returned vector contains both gates and measurements; depth counts unitary layers, not individual operations. This uses the package's discrete gate family and random rotation parameters, rather than Haar-random two-qubit unitaries.

Example

ops = random_ops(5, 10; measure_prob=0.2, measure_basis=["MX","MZ"])

This creates ten unitary layers on five qubits, each followed by independently chosen X- or Z-basis measurements with probability 0.2 per qubit.

BlueTangle.random_clifford — Function
random_clifford(N::Int, len::Int; measure_prob=0.0, measure_basis=["MX", "MY", "MZ"])

Choose len gates independently from X, Y, Z, H, S, CNOT, SWAP, and CZ. Two-qubit gates act on a randomly chosen adjacent pair; single-qubit gates act on a random qubit. For N=1, only the one-qubit gates are used. This constructs a random gate sequence, without sampling uniformly from the Clifford group.

After each gate, add a measurement with probability measure_prob, choosing a random qubit and a basis uniformly from measure_basis. Measurements are additional operations, so the returned vector can contain more than len entries.

Example

ops = random_clifford(5, 10; measure_prob=0.2, measure_basis=["MX","MZ"])

This creates ten Clifford gates on five qubits, with a 20% probability of adding an X- or Z-basis measurement after each gate.

BlueTangle.is_valid_quantum_channel — Function
is_valid_quantum_channel(kraus::Vector) -> Bool

Checks for a nonempty list of finite square matrices of the same size and the trace-preserving condition sum(K' * K for K in kraus) ≈ I. Complete positivity already follows from the Kraus representation. Returns false for malformed operators; supported qubit counts are checked separately by the constructors.

BlueTangle.cnot_amplifier! — Function
cnot_amplifier!(ops::Vector{<:QuantumOps}, CNOT_pair=0)

Insert CNOT_pair extra pairs before every operation named "CNOT" or "CX", modifying ops in place. For standard CNOT gates each pair is an ideal identity, so the circuit's ideal action is preserved while its gate-noise exposure grows. The inserted operations retain the original gate's noisy setting.

Examples

ops = [Op("H",1), Op("CNOT",1,2), Op("X",2)]
cnot_amplifier!(ops, 1)
# `ops` will be modified to: [Op("H",1), Op("CNOT",1,2), Op("CNOT",1,2), Op("CNOT",1,2), Op("X",2)]

op_amplifier!(ops::Vector{<:QuantumOps}, op_pair=0)

Insert 2*op_pair copies before every operation, modifying ops in place. For gates that square to the identity, each repeated pair preserves the ideal action. General rotations, channels, and measurements can change the computation when repeated this way.

Hamiltonian

BlueTangle.hamiltonian — Function
hamiltonian(N::Int, string_of_ops::Vector, boundary::String="open")

Construct a sparse Hamiltonian for an N-qubit chain. string_of_ops alternates coupling constants and comma-separated operator strings. Each string is summed over consecutive sites; for example, [.1, "Z,Z", .5, "X"] gives 0.1*sum(Z_i*Z_{i+1}) + 0.5*sum(X_i).

With boundary="open", include only strings that fit within the chain. With "periodic", start a term at every site and wrap its indices around the chain. This convention can count the same operator more than once on short periodic chains.

Example

N = 6
J, h = 1.0, 0.7
string_of_ops = [-J, "Z,Z", -h, "X"]
H = hamiltonian(N, string_of_ops, "open")
source
hamiltonian(rows_cols::Union{Tuple{Int64, Int64},Vector{Int64}}, string_of_ops::Vector, boundary::String="open")

Construct a sparse Hamiltonian on a rectangular lattice of (rows, columns) qubits, numbered row by row. The terms use the same alternating couplings and operator strings as the chain method. Multi-site strings run along both rows and columns; single-site terms are counted once.

Choose "open" or "periodic" boundaries. Periodic terms start at every site in each direction, so different starting sites can produce the same operator on short periodic dimensions.

BlueTangle.hamiltonian_exp — Function
hamiltonian_exp(N, total_time, terms; dt=0.01, order=1, full=true)
hamiltonian_exp((rows, cols), total_time, terms; dt=0.01, order=1, full=true, enumeration_style=:rowwise)

Construct a product-formula approximation to exp(-im*total_time*H) for H = hamiltonian(N, terms) with open boundaries. terms alternates real couplings and comma-separated Pauli strings, for example [0.7, "X,Z", 0.2, "Y"]. Identity factors preserve the separation between the active sites. In 2D, strings run along both lattice directions; single-site terms are counted once.

Choose order=1 (Lie–Trotter, the default), order=2 (symmetric Strang), or order=4 (Yoshida's three-stage composition). At fixed total time their errors scale as dt, dt^2, and dt^4 in the small-step limit. Fourth order uses S2(w*dt) S2((1-2w)*dt) S2(w*dt), where w = 1/(2-cbrt(2)); its middle stage runs backwards. This uses fewer stages than the five-stage Suzuki formula, but is not guaranteed to minimize gates at a prescribed error for every model. See Yoshida (1990).

Consecutive commuting local terms form exact blocks, and adjacent repetitions of a block are merged across stages and time steps. Zero couplings are omitted; single-site factors use one RX/RY/RZ gate. General Pauli strings use basis rotations and 2(k-1) CNOTs for k nonidentity sites. Identity factors retain their global phase. The returned operation list does not store a register size; apply it to an explicitly sized state when some qubits are idle.

The last step is shortened to reach the requested time exactly. full=false returns just one step of duration dt (with the sign of total_time, positive when it is zero). For example, hamiltonian_exp(4, 0.6, [-1.0, "Z,Z", -0.8, "X"]; dt=0.05, order=2) constructs second-order open-chain Ising evolution.

evolve(state, H, time)

Exact evolution by exp(-im*time*H) for a statevector or density matrix. This materializes the matrix exponential; use hamiltonian_exp for a circuit approximation when the full Hilbert-space matrix is too large.
